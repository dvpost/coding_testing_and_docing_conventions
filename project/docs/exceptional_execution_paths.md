# Exceptional Execution Paths — реестр разрешённых исключительных путей

**Статус:** документ текущего состояния. **Канонический путь в сервисе:** `docs/exceptional_execution_paths.md`.

Правила записей и сверки: [convention-coding — реестр исключительных путей](../.agents/skills/convention-coding/references/exceptional-execution-paths.md). В реестр включать только действующие одобренные механизмы с отдельным EXC-ID, точными путями/символами/настройками, условиями, лимитами, обоснованием, согласованием человека-оператора и тестами.

**Статус проверки: NOT ASSESSED.**

Это первоначальный шаблон, а не утверждение об отсутствии retry/fallback. Провести двустороннюю сверку кода, SDK и конфигураций с реестром. Только после подтверждённого аудита заменить статус на `VERIFIED` и внести подтверждённые действующие одобренные записи либо фразу «Утверждённых активных исключений нет». Неподтверждённые механизмы и задачи исправления фиксировать только в `TODO/`. `NOT ASSESSED` не означает соответствие.
