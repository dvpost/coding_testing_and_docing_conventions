# Exceptional Execution Paths — реестр разрешённых исключительных путей

**Статус:** документ текущего состояния. **Канонический путь в сервисе:** `docs/exceptional_execution_paths.md`.

**Правила:** см. раздел 12 файла `coding_testing_and_docing_conventions.md`. В реестре допускаются **только действующие, явно согласованные оператором** retry, fallback, деградации и другие исключения из принципа ONE PATH / FAIL EXPLICITLY. Каждая запись обязана иметь уникальный ID `EXC-...`, точные пути и символы/настройки в коде, конкретные условия и ограничения, проверяемое обоснование, доказательство согласования оператором и тесты. Код и реестр проверяются в обе стороны.

**Статус проверки: NOT ASSESSED.**

Это **начальный шаблон, а не утверждение об отсутствии retry/fallback в проекте**. Сначала проведите аудит в обе стороны (код, SDK и конфигурации ↔ реестр). Если проверено, что действующих одобренных механизмов нет, замените статус на `VERIFIED` и напишите: **«Утверждённых активных исключений нет»**. Если такие механизмы есть, добавьте только подтверждённые активные записи по разделу 12 конвенции; неподтверждённые случаи зафиксируйте как несоответствия исключительно в `TODO/`. `NOT ASSESSED` не даёт права объявить сервис соответствующим стандарту.
