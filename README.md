# Coding, Testing & Documentation Conventions

Общий набор правил разработки, тестирования и документации для проектов, в которых работают AI-агенты. Применим к новым и существующим сервисам независимо от языка и фреймворка.

**Готовый набор для подключения находится в [project/](project/). Его содержимое объединяется с существующей структурой проекта-потребителя по правилам подключения.**

## Состав

```text
project/
├── .agents/skills/convention-*/   # Пять канонических навыков со справочниками
├── .claude/skills/convention-*/   # Короткие адаптеры Claude Code
├── AGENTS.md                     # Общая директива и локальная ссылка
├── CLAUDE.md                     # Импорт @AGENTS.md
└── docs/
    ├── conventions/README.md     # Индекс, источник и версия пакета
    └── exceptional_execution_paths.md # Начальный реестр: NOT ASSESSED
```

Назначение навыков, версия и подробности подключения: [индекс пакета](project/docs/conventions/README.md). Корневые AGENTS.md и CLAUDE.md относятся к работе над этим репозиторием; для проектов используются файлы внутри `project/`.

## Подключение и обновление

Получить выбранную редакцию удобным способом и объединить содержимое `project/`, включая скрытые каталоги, со структурой в корне своего проекта. Отсутствующие файлы создать, совпадающие пути обработать по правилам ниже. Все относительные ссылки уже подготовлены; установщик, symlink, пользовательская настройка и исправление путей не нужны.

Навыки `convention-*` и индекс пакета устанавливаются или заменяются целиком; AGENTS и CLAUDE объединяются с местными инструкциями. Существующий реестр исключений, собственные навыки, конфигурации и остальные документы сохраняются. Перед заменой файлов пакета уникальные сведения проекта вынести в подходящие проектные документы или навыки. Эти правила действуют и при первом подключении, и при обновлении; подробности — в [инструкции подключения и обновления](project/docs/conventions/README.md#подключение).

После первого подключения в существующий проект агент в итоговом отчёте рекомендует перезапустить агентное приложение и начать новую сессию в этом проекте, затем проверить обнаружение навыков и применение workflow. Динамическое обнаружение навыков и условия обновления контекста описаны в [проверке подключения](project/docs/conventions/README.md#проверка-подключения).

## Обслуживание

Канонические требования редактируются только внутри `project/.agents/skills/`; каждый подробный пункт имеет одно место. При изменении имени или description навыка обновить также соответствующий Claude-адаптер. Требования оформления точек входа и документов находятся в навыках; этот README описывает поставку и работу над пакетом.

Все поставляемые ссылки должны работать относительно корня `project/` и после подключения его содержимого в другом проекте без переписывания. В самом репозитории конвенции корневой AGENTS явно направляет к каноническому workflow внутри `project/`; вторые наборы навыков в корне не поддерживаются.

Редакции используют [CalVer](https://calver.org/): `ГГГГ.ММ.N` (`YYYY.0M.MICRO`), год и двузначный месяц публикации по UTC, номер редакции без ведущих нулей. N начинается с 1 каждый месяц и увеличивается для каждой следующей опубликованной редакции, включая текстовые исправления. Промежуточные коммиты одной редакции не требуют нового номера. Канонический номер — поле «Версия» в [README пакета](project/docs/conventions/README.md); в SKILL, AGENTS и корневом README номер не дублируется.

Перед публикацией зафиксировать редакцию коммитом и создать аннотированный тег `vГГГГ.ММ.N` с тем же номером; публиковать тег вместе с коммитом. Опубликованные теги неизменяемы. Эта схема относится к пакету конвенции; версии сервисов и API определяются их контрактами. Совместимость новой редакции оценивать по содержанию требований. Действующие правила описывать без хроники редакций; историю хранит Git.

Проверять полноту требований, frontmatter всех навыков, соответствие адаптеров, относительные ссылки и `git diff --check`. В изолированном проекте проверить подключение `project/` без изменения ссылок и обновление с сохранением собственного навыка, местных инструкций и заполненного реестра. В свежих сессиях Codex и Claude Code проверить обнаружение из корня и подкаталога, применение workflow, выбор тематического навыка и чтение канонических требований через адаптер. Проверки и их ограничения сообщать в отчёте изменения.
